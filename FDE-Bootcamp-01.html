1.1 确定公司主体

5 分钟
  • WHAT：识别客户的母公司、子公司、业务板块及所属行业地位
  • WHY：明确需求归属的组织架构，确保调研范围精准，了解企业的核心战略诉求
  • 工具：AgentOS 企业全景规划、财报库、LinkedIn、公司官网、搜索引擎

实操指南 (HOW)

借助 AgentOS 桌研
在进入客户现场前，FDE 必须通过远程桌研建立对客户的基本认知： 1. **输入商机信息**：在 AgentOS 中输入商机名称和已知背景。 2. **调取财报与组织数据**：利用 AgentOS 自动抓取客户近三年的财报（如 10-K）或官方招股书，并提取“Segment Reporting”板块。 3. **识别核心业务与战略**：利用 AgentOS 总结其组织规模、全球分布以及最新的重大战略动作（如“AI First”战略）。 4. **输出结构化报告**：生成包含股权结构、核心业务占比、年度战略关键词的公司主体研究报告。

产出

公司主体研究报告（包含股权结构、核心业务占比、年度战略关键词）

产出示例

伊利奶粉事业部的分仓补货业务，覆盖从生产工厂、基地仓、销售分仓，到线上线下渠道客户的供应链补货链路。 整体链路可以概括为： 工厂 / 基地仓 → 销售分仓 → 电商及经销商 → 终端客户 业务涉及的上游节点包括： - 8 个国内工厂 - 1 个 ODL 工厂 - 4 个基地仓 - 多个区域销售分仓 - 线上电商渠道与线下经销商渠道 其中，基地仓包括天津基地仓、呼市基地仓、杜蒙基地仓、武汉基地仓等；销售分仓包括合肥、天津、广州、郑州、成都、武汉、呼市、济南、柳州等销售仓。 **组织边界** - **组织范围**：伊利奶粉事业部 - **业务范围**：伊利奶粉事业部所属生产工厂到各分仓的补货业务 - **商品范围**：伊利奶粉事业部经营的所有在售商品，不包含促销品及礼盒 - **覆盖供应链网络节点**：工厂仓、区域分仓 - **渠道范围**：线上电商、线下经销商

实践提示

重点关注财报中提到的“Risk Factors”。如果提到“人力成本上升”或“交付效率瓶颈”，这就是 AI 介入的绝佳切入点。不要只看官网的 PR 稿，财报里的风险警示往往才是业务负责人的真实痛点。

1.2 企业画像

5 分钟
  • WHAT：建立对客户企业的全方位认知，包含企业基座、组织规模、业务组合、数字化成熟度、战略痛点及决策链
  • WHY：将模糊的商机背景具象化，识别业务增长引擎与数字化 Gap，为后续场景拆解提供战略依据
  • 工具：AgentOS 企业画像 Agent、财报库、行业研报、LinkedIn

实操指南 (HOW)

借助 AgentOS 桌研
基于 FDE 提供的商机初步信息，利用 AgentOS 构建结构化的企业认知： 1. **分析核心增长曲线**：输入行业数据，提取其核心业务（如伊利的奶粉业务）及毛利表现。 2. **盘点数字化底座**：利用 AgentOS 提取客户在 IT 基础设施上的投资（如 APS、ERP、BI），识别数字化 Gap。 3. **推演决策链角色**：通过 LinkedIn 数据或相关访谈，在 AgentOS 中推断 Sponsor、决策者、使用者等角色的核心关切。 4. **生成初稿**：输出一份“可判断、可对齐、可支撑下游拆解”的企业认知初稿。

产出

企业画像报告（包含企业基座、业务结构、数字化现状及战略痛点）

产出示例

# 伊利奶粉事业部 · 企业画像初稿 **1 总览** 奶粉是伊利集团第二增长曲线——2024年营收 296.75 亿元。商机要解决的「分仓补货计划」，正是这条高毛利增长曲线里连接生产、仓储、渠道的枢纽环节，目前仍以人工 Excel 推式分货为主。 **2 企业基座** - **法定全称**：内蒙古伊利实业集团股份有限公司 - **董事长**：潘刚 - **全球地位**：全球乳业五强，连续十二年亚洲乳业第一 **3 组织规模** - **集团 2024 营业总收入**：1157.80 亿元 - **奶粉及奶制品营收**：296.75 亿元（同比 +7.53%） **4 业务组合与收入结构** - **婴幼儿配方奶粉市占**：17.3%，居行业第二 - **成人奶粉市占**：24%，稳居细分市场第一 - **主要品牌**：金领冠、欣活、托菲儿、塞纳牧、悠滋小羊、佳贝艾特 **5 数字化成熟度** - **已有能力**：APS 排产、云商系统、京东「一盘货」、阿里云 BI - **关键 Gap**：贯穿“生产工厂 → 基地仓 → 销售分仓 → 全渠道”的端到端分仓补货计划，仍是人工 Excel 推式分货。 **6 战略痛点** 1. 分货效率低（人工 Excel） 2. 分仓有货率不足（货没在对的仓） 3. 库存周转率低 4. 商品新鲜度差 5. 跨仓履约率高

实践提示

不要只盯着“人”，要先看清“事”。在做企业画像时，优先通过公开财报识别出企业的“钱袋子”在哪里，这决定了项目的战略天花板。同时，要识别出决策链中那些掌握“否决权”的隐形角色，确保方案能够兼顾多方利益。

1.3 商业模式与价值流分析

7 分钟

企业业务价值流分析方法论

1. WHAT｜什么是价值流分析

定义：围绕特定利益相关者，从业务触发开始，经由多个价值创造阶段，最终形成业务价值结果的端到端路径。

核心概念

概念 含义
Stakeholder为谁创造价值
Trigger什么触发价值流
Value Proposition最终创造什么价值
Value Stream完整的端到端价值创造
Value Stream Stage价值创造中的关键阶段
Outcome / Value Item阶段性/最终产生的价值结果
Capability支撑价值创造的业务能力
Process具体执行方式
KPI衡量价值创造效果
Stakeholder → Trigger → Value Stream → Value Stream Stage → Outcome
                    ↓
                Capability / Process / KPI

示例：需求与供应计划

需求识别 → 需求预测 → 供给配置 → 库存平衡 → 计划确认

最终实现：将市场需求转化为可执行的供需决策，实现需求满足与库存效率的平衡。

2. WHY｜为什么做价值流分析

  • 看价值：从部门/流程视角转向端到端价值视角
  • 找断点：识别价值创造中的阻塞、浪费和损失
  • 建架构：连接战略、价值流、能力、流程和 IT
  • 促转型：找到业务优化、数字化和 AI 的价值机会
核心目的：不是把流程画全，而是看清“价值如何产生、在哪里损失、如何提升”。

3. HOW｜如何开展价值流分析

① 明确范围：业务领域、价值对象、核心 Stakeholder
↓
② 识别价值流：从经营目标出发识别企业核心端到端价值流
↓
③ 定义价值流：明确 Trigger、Value Proposition、Outcome
↓
④ 拆解 Stage：识别 4–7 个关键价值创造阶段
↓
⑤ 建立映射：Value Stream / Stage → Capability → Process → System
↓
⑥ 识别优化机会：价值损失 → 能力差距 → 数字化 / AI 机会 → KPI

4. 判断标准（六看）

判断维度 核心问题
看价值是否明确创造什么业务价值？
看边界Trigger 和 Outcome 是否清晰？
看端到端是否形成完整价值闭环？
看 Stage是否体现价值递进，而非简单流程步骤？
看粒度同层级价值流是否保持一致粒度？
看结果是否能够关联经营结果和 KPI？
好的价值流分析 = 价值清晰 + 边界合理 + 端到端 + 阶段递进 + 粒度一致 + 可衡量

⚠️ 警惕：把部门、流程、系统或具体操作直接当成 Value Stream

实操指南 (HOW)

借助 AgentOS 桌研
利用 AgentOS 完成端到端价值流梳理，弥补 60% 的业务认知空白： 1. **明确范围**：在 AgentOS 中输入企业信息，明确业务领域、价值对象及核心 Stakeholder。 2. **定义价值流**：通过 AgentOS 的行业知识库，生成该企业的端到端价值流，明确 Trigger、Value Proposition 与 Outcome。 3. **拆解 Stage 与建立映射**：利用 AgentOS 识别 4–7 个关键价值创造阶段，并建立“Value Stream → Capability → Process → System”的映射。 4. **识别优化机会**：通过 AgentOS 找出各阶段的价值损失与能力差距，定位数字化/AI 的介入机会点。

产出

业务价值流图 (As-is) 与关键交付物清单

产出示例

# 伊利奶粉事业部 · 业务现状全景图 (价值流) **1 总览** 把伊利奶粉事业部的端到端经营拆成 5 条价值流。聚焦范围落在两个连续段：价值流②「需求与供应计划」与价值流④「仓储物流与履约」。 **2 高阶价值框架** - **聚焦范围 ①（价值流② 需求与供应计划）**：销售计划与需求预测 → 分货与补货计划 → 库存计划。对应：销售计划精细化 + 分仓智能补货优化。 - **聚焦范围 ②（价值流④ 仓储物流与履约）**：销售分仓管理与横向调拨 → 订单履约与配送。对应：销售仓横向调拨。 **3 核心洞察** 价值流②内部呈现一条清晰因果链——"人工 Excel 推式分货"是上游根因，"有货率不足 / 周转慢 / 新鲜度差 / 跨仓履约高"是下游结果。

实践提示

带一份“可能有错的假设”去现场，比带一张白纸去问客户“你们流程是啥”要高效得多。客户会更愿意纠正你的错误，从而在纠错过程中吐露真实的业务逻辑。

2.1 背景与场景沟通

4 分钟
  • WHAT：与核心干系人深度面谈，对齐商机需求背后的业务全景与真实痛点
  • WHY：确认桌研假设的准确性，识别隐藏的业务约束和干系人的利益关切
  • 工具：访谈提纲、价值流初稿 (50%-ready)

实操指南 (HOW)

客户沟通
**1. 从 AgentOS 衔接出沟通/调研事项** - 审查 AgentOS 输出的“企业画像”与“假设痛点”，梳理出 3-5 个需要向客户求证的核心疑问（例如：“推式分货是否是履约成本高的主因？”）。 **2. 结合调研事项，准备沟通计划** - 确定沟通对象（如物流计划负责人、Sponsor）。 - 准备好基于 AgentOS 生成的 50%-ready 价值流图作为“讨论靶子”。 **3. 如何沟通 (执行)** - **切入**：展示 50%-ready 价值流图，将对话从抽象的“AI”转变为具体的业务探讨。 - **追问**：不问“你们要什么功能”，而问“当前流程中哪里最痛？”利用“黄金圈法则”深挖“Why”。 - **识别隐形流程**：重点挖掘用于弥补系统缺陷的“离线 Excel 表格”或“人工经验规则”。 **4. 沟通注意事项** - ⚠️ 不要陷入技术实现细节，死守“业务痛点与价值”的主线。 - ⚠️ 记录干系人的原话和特殊术语，后续全流程保持术语一致。

产出

调研焦点对齐纪要（包含核心痛点假设确认、现场调研计划）

产出示例

2.2 流程建模

6 分钟
  • WHAT：选定最具代表性的业务线，还原 L2/L3 级细颗粒度的业务流程蓝图
  • WHY：建立统一的业务“作战地图”，确保 AI 场景的定义不会脱离实际业务语境
  • 工具：SIPOC 模板、影子跟随 (Job Shadowing) 记录表

实操指南 (HOW)

借助 AgentOS 桌研
利用 AgentOS 的逻辑梳理能力，将沟通访谈中获得的碎片化信息转化为结构化的业务蓝图： 1. **输入访谈纪要**：将沟通记录和业务资料输入 AgentOS。 2. **生成 L2/L3 流程框架**：让 AgentOS 还原主干动作（L2）并在关键节点下钻到原子动作（L3）。 3. **识别信息断点**：通过 AgentOS 分析找出流程中的“断层”：哪里需要人工跨系统搬运？哪里需要离线确认？ 4. **输出流程草图**：利用 AgentOS 生成一份标准的业务流程蓝图（As-is Blueprint），作为下一步“痛点推导”的地基。

2.3 瓶颈与痛点推导

5 分钟
  • WHAT：基于流程蓝图，分析高认知负荷、高错误率及长停顿的环节
  • WHY：量化业务损失，识别出 AI 最能发挥“雪中送炭”作用的硬骨头场景
  • 工具：认知负荷分析模型、痛点热力图

实操指南 (HOW)

客户现场调研
**1. 从 AgentOS 衔接出调研事项** - 基于 AgentOS 输出的流程蓝图，标注出 3-5 个“疑似高认知负荷/高耗时”的节点（如：手工查算历史数据的环节）。 **2. 结合调研事项，准备调研计划** - 选择这些高负荷节点的具体操作员工进行“影子跟随 (Job Shadowing)”。 - 准备好秒表或计时器，以及用于记录系统间切换次数的模板。 **3. 如何调研 (执行)** - **影子跟随**：坐在员工旁边，观察其处理业务的全过程，记录真实的操作时长、系统切换次数和报错率。 - **痛点热力图**：根据观察结果，在流程图上标记出“等待”、“返工”的密集区。 - **公式化表达**：用 `[角色] 在 [具体环节] 遇到 [具体障碍]，导致了 [可量化的业务损失]` 的公式记录痛点。 **4. 调研注意事项** - ⚠️ 痛点必须用数据支撑。如果用户说“这里慢”，必须追问并测算“上周在这里花了多少小时？”。 - ⚠️ 观察而非干预，不要在员工操作时打断或建议“你们为什么不用某某系统”。

痛点描述要符合公式：[角色] 在 [环节] 因为 [原因] 导致了 [具体的业务后果/损失]。痛点必须是“真实的”。如果用户说“我觉得这里慢”，你要追问“上周你在这个环节花了多少时间？”用数据说话，而非感觉。

2.4 识别 AI 机会点

5 分钟
  • WHAT：将业务痛点映射到 AI 技术能力上，识别潜在的 AI 场景机会
  • WHY：明确 AI 在该场景下的角色：是“全自动机器人”还是“专家的智能助手”
  • 工具：AI 机会点匹配框架、AgentOS 架构推荐引擎

实操指南 (HOW)

客户现场调研
**1. 从 AgentOS 衔接出调研事项** - 将上一步生成的“痛点清单”输入 AgentOS，生成“AI 技术能力匹配假设”（如：海量非结构化检索对应 RAG，多约束优化对应运筹算法）。 **2. 结合调研事项，准备调研计划** - 组织客户侧的业务专家和技术负责人，准备一场机会点研讨会。 - 准备好展示技术可行性的案例 Demo 或能力矩阵。 **3. 如何调研 (执行)** - **映射痛点**：在研讨会上，将业务痛点逐一映射到具体的 AI 技术能力上。 - **界定 AI 角色**：明确 AI 是作为“辅助生成 (Co-pilot)”还是“自主执行 (Autopilot)”。 - **产出清单**：共创出初步的需求场景清单 (SLP)，包含每个场景的初步价值预估。 **4. 调研注意事项** - ⚠️ 抑制客户对“全自动机器人”的不切实际期望，优先推销“专家助手”模式。 - ⚠️ 确保每一个 AI 机会点都能对应到一个之前确认过的“真实业务痛点”。

2.5 优先级评估

5 分钟
  • WHAT：从业务价值和实现难度两个维度对场景进行打分筛选，锁定首个 MVP
  • WHY：确保有限的研发资源投入在“高 ROI”且“能落地”的场景上
  • 工具：价值-可行性四象限、数据准备度评估表

实操指南 (HOW)

借助 AgentOS 桌研
利用 AgentOS 进行数据驱动的优先级评估，确保资源投入到高 ROI 的场景： 1. **录入场景数据**：将初步 SLP 清单及现场获取的数据情况输入 AgentOS。 2. **多维打分推演**：利用 AgentOS 预置的评估模型，从业务价值（降本增效幅度、Sponsor 关注度）和技术可行性（数据质量、大模型能力边界）两个维度进行模拟打分。 3. **识别数据风险**：通过 AgentOS 的合规引擎分析场景是否涉及敏感数据或缺乏历史语料，输出“数据准备度 (Data Readiness)”警告。 4. **生成优先级矩阵**：AgentOS 自动绘制“价值-可行性四象限图”，推荐位于“Quick Win”象限的首批 MVP 场景。

3.1 需求目标与 KPI

4 分钟
  • WHAT：将场景成效与客户的战略 KPI 进行强绑定，定义清晰的成功指标
  • WHY：让 AI 的价值从“玄学”变成“数学”，为项目立项和 ROI 测算提供决策依据
  • 工具：OSM 模型、业务基准 (Baseline) 数据表

实操指南 (HOW)

客户沟通

实践提示

KPI 必须是客户现有系统能统计出来的。如果你定义了一个系统无法监控的指标，那么在项目结束时，你将无法证明 AI 到底带来了多少价值。确保指标的可追溯性。

3.2 业务动作识别

6 分钟
  • WHAT：拆解 AI 介入后，人与 AI 交互的具体业务动作序列
  • WHY：识别数据输入的来源、AI 处理的逻辑断点以及人工复核的心理阈值

借助 AgentOS 桌研
利用 AgentOS 的逻辑编排能力，拆解 To-be 流程的“原子动作序列”： 1. **输入现状与目标**：将 As-is 流程和业务 KPI 输入 AgentOS。 2. **生成原子动作**：让 AgentOS 拆解出人与 AI 交互的具体序列（用户上传什么？AI 提取什么？在哪里等待人工确认？）。 3. **识别数据依赖**：通过 AgentOS 分析每个动作所需的上下文数据 (Context)。 4. **划定人机边界**：明确哪些动作是 AI 建议，哪些是必须由人执行的终审决策。

3.3 数据知识探查

7 分钟
  • WHAT：识别支撑 AI 场景所需的原始数据源、知识文档及数据质量评估
  • WHY：数据是 AI 的燃料，提前探查数据分布和质量，决定了 RAG 检索的准确率和 Agent 的执行边界

实操指南 (HOW)

借助 AgentOS 桌研
利用 AgentOS 的数据探索能力，全面评估业务知识资产： 1. **构建知识地图**：通过 AgentOS 梳理出支撑业务动作所需的数据分布在哪些孤岛（如 SharePoint, Salesforce, Wiki）。 2. **自动化样本初筛**：抽取 10-20 份历史文档（如 SOW 或计划表），利用 AgentOS 进行自动化清洗与结构化解析，评估数据“噪声比”。 3. **权限与合规扫描**：在 AgentOS 中推演数据权限边界，确认未来 AI Agent 是否具备合法且通畅的访问路径。 4. **输出治理建议**：如果原始数据质量极差，则利用 AgentOS 生成“知识治理”建议报告，防止“垃圾进，垃圾出”。

3.4 场景画布与指标

  • WHY：产出场景需求规格说明书 (SRP)，作为后续 AI 研发和 Prompt 工程的唯一输入标准
  • 工具：AI Opportunity Canvas、MoS 指标体系

实操指南 (HOW)

客户现场共创

# 分仓智能补货 · 场景定义画布 (SRP) **1 场景基础信息** - **名称**：分仓智能补货 - **面向角色**：物流计划、调度组 - **痛点锚定**：多仓×多SKU×多约束（库存/在途/待检/效期）人工 Excel 无法全局最优。 **2 AI 机会定义** - **AI 任务**：多约束库存分配优化 (OR/运筹优化)。 - **AI 角色**：物流计划员的智能调度助手。 - **业务价值**：提升分货效率、有货率、周转率与新鲜度。 **3 成功度指标 (MoS)** - **可用率**：AI 生成的分货建议初稿采纳率 > 80%。 - **准确度**：模型预测补货量与实际发货量的偏离度 < 10%。 - **提效**：分货计划编制时间缩减 60% 以上。 **4 关联系统与数据** - **系统**：APS、云商、WMS。 - **数据**：待检/合格/在途库存、历史销量、促销计划、效期批次。

实践提示

MoS 指标要尽量客观。与其问用户“你觉得 AI 写得好吗”，不如统计“用户在 AI 生成的内容上修改了多少个字符”。用客观的行为指标来衡量 AI 的表现。

实操指南 (HOW)

客户现场共创
**1. 共创 Agenda** - 第一部分（15min）：展示基于 As-is 简化的 To-be 旅程草图。 - 第二部分（30min）：基于草图共创原型线框。 - 第三部分（15min）：对齐交互逻辑，锁定交付预期。 **2. 共创准备** - 提前准备好白板或低代码原型工具，以及现状 As-is 流程图。 - 确保关键的用户代表（一线使用者）在场。 **3. 共创过程 Facilitate** - **To-be 旅程推演**：带领客户走查未来数字化的用户旅程，确认哪些繁琐的步骤被消减。 - **画草图/原型**：在白板上或使用低代码工具，与客户共同勾勒出界面的核心元素（AI 按钮在哪里？AI 建议如何弹出？修改后的内容如何回填？）。 - **原型走查**：让业务人员在草图或低保真原型上“走查”真实业务流程，暴露潜在的交互盲区。 **4. 如何得出共创结论** - 根据走查反馈，FDE 在现场修正原型逻辑。 - 确认“可视即价值”的原型方案（哪怕是高保真图纸），让客户签字确认，锁定最终的开发预期。

4. 总结与实操

5 分钟
学习知识点
理需求全流程回顾、AgentOS 实操演示、Q&A

1. 全流程回顾

  • 理需求三部曲：懂业务 (客户研究) -> 找痛点 (场景发现) -> 定方案 (场景定义)
  • 核心价值：通过“理需求”将模糊的客户诉求转化为结构化的 AI 场景规划 (SRP)，为后续交付打好地基

2. AgentOS 实操演示 (关键环节展示)

  • 桌研提效演示 (Desk Research)
    • 演示如何使用 AgentOS 聚合搜索 Ascentium 及伊利奶粉所在的行业报告，并在 30 秒内提取出核心价值流模型
    • 展示如何通过 AgentOS 对 20 份历史访谈录音或业务痛点记录进行语义聚类，自动生成包含“痛点频率”的热力图（如伊利的“跨仓履约”痛点）
  • 共创产出演示 (Co-creation)
    • 演示如何使用 AgentOS 辅助生成初版“场景画布”：输入痛点清单，AI 自动推荐 RAG + Agent 或大模型智能补货调度的架构组合
    • 展示基于 Ascentium 与伊利业务逻辑自动推演出的 MoS 指标建议（包含数据获取方式说明）

3. 核心精神总结

  • 以业务价值为导向：所有的 AI 场景必须最终关联到客户的战略 KPI
  • Start with 50%-ready：善用 AgentOS 提效，永远带着“假设”去共创
  • 可视 = 价值：用原型 and Demo 锁定客户预期，减少交付偏差
