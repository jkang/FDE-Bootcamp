1.1 确定公司主体

5 分钟
  • WHAT：识别客户的母公司、子公司、业务板块及所属行业地位
  • WHY：明确需求归属的组织架构，确保调研范围精准，了解企业的核心战略诉求
  • 工具：AgentOS 企业全景规划、财报库、LinkedIn、公司官网、搜索引擎

实操指南 (HOW)

活动类型：桌研
**AgentOS 衔接与操作逻辑：** 1. **输入商机信息**：在 AgentOS 中输入商机名称和已知背景（如“伊利奶粉智能分仓补货”）。 2. **调取财报与组织数据**：利用 AgentOS 自动抓取客户近三年的财报（如 10-K）或官方招股书，并提取“Segment Reporting”板块。 3. **识别核心业务与战略**：利用 AgentOS 总结其组织规模、全球分布以及最新的重大战略动作（如“AI First”战略）。 4. **输出结构化报告**：生成包含股权结构、核心业务占比、年度战略关键词的公司主体研究报告。

产出

公司主体研究报告（包含股权结构、核心业务占比、年度战略关键词）

产出示例

伊利奶粉事业部的分仓补货业务，覆盖从生产工厂、基地仓、销售分仓，到线上线下渠道客户的供应链补货链路。 整体链路可以概括为： 工厂 / 基地仓 → 销售分仓 → 电商及经销商 → 终端客户 业务涉及的上游节点包括： 8 个国内工厂 1 个 ODL 工厂 4 个基地仓 多个区域销售分仓 线上电商渠道与线下经销商渠道 其中，基地仓包括天津基地仓、呼市基地仓、杜蒙基地仓、武汉基地仓等；销售分仓包括合肥、天津、广州、郑州、成都、武汉、呼市、济南、柳州等销售仓。 **组织边界** - **组织范围**：伊利奶粉事业部 - **业务范围**：伊利奶粉事业部所属生产工厂到各分仓的补货业务 - **商品范围**：伊利奶粉事业部经营的所有在售商品，不包含促销品及礼盒 - **覆盖供应链网络节点**：工厂仓、区域分仓 - **渠道范围**：线上电商、线下经销商 **业务本质和目标** 未来需要建立一套面向奶粉事业部的分仓补货计划机制，使生产、物流、销售分仓 and 渠道需求之间形成更高效、更准确、更可控的协同关系。奶粉业务具有较强的供应链复杂性： - 渠道多，包括线上电商、KA 客户、经销商、母婴、商超、特渠等 - 仓网多，包括工厂仓、基地仓、区域分仓 - 商品对日期 and 新鲜度敏感 - 区域需求波动明显 - 缺货会影响订单满足 and 客户体验 - 库存过高会影响周转 and 新鲜度 因此，分仓补货计划既要解决“货够不够”的问题，也要解决“货在哪里、是否新鲜、是否在正确的仓、能否及时满足订单”的问题。

实践提示

重点关注财报中提到的“Risk Factors”。如果提到“人力成本上升”或“交付效率瓶颈”，这就是 AI 介入的绝佳切入点。不要只看官网的 PR 稿，财报里的风险警示往往才是业务负责人的真实痛点。

1.2 企业画像

5 分钟
  • WHAT：建立对客户企业的全方位认知，包含企业基座、组织规模、业务组合、数字化成熟度、战略痛点及决策链
  • WHY：将模糊的商机背景具象化，识别业务增长引擎与数字化 Gap，为后续场景拆解提供战略依据
  • 工具：AgentOS 企业画像 Agent、财报库、行业研报、LinkedIn

实操指南 (HOW)

活动类型：桌研
**AgentOS 操作逻辑：** 1. **背景注入**：在 AgentOS 企业画像 Agent 中输入“伊利奶粉智能分仓补货”商商机名称及初始背景。 2. **多维采集**：Agent 自动抓取公开财报（2024年报）、行业报告（尼尔森）及新闻动态，补全企业基座与组织规模。 3. **数字化对齐**：通过 Agent 检索伊利已有的数字化底座（APS、云商、一盘货），自动比对出补货计划环节的数字化空白。 4. **痛点预判**：Agent 基于供应链通用逻辑，预判出分货效率、有货率、周转、新鲜度、跨仓履约五大痛点，生成“50%-ready”的初稿报告。

1.3 商业模式与价值流分析

7 分钟

企业业务价值流分析方法论

1. WHAT｜什么是价值流分析

定义：围绕特定利益相关者，从业务触发开始，经由多个价值创造阶段，最终形成业务价值结果的端到端路径。

核心概念

概念 含义
Stakeholder为谁创造价值
Trigger什么触发价值流
Value Proposition最终创造什么价值
Value Stream完整的端到端价值创造
Value Stream Stage价值创造中的关键阶段
Outcome / Value Item阶段性/最终产生的价值结果
Capability支撑价值创造的业务能力
Process具体执行方式
KPI衡量价值创造效果
Stakeholder → Trigger → Value Stream → Value Stream Stage → Outcome
                    ↓
                Capability / Process / KPI

示例：需求与供应计划

需求识别 → 需求预测 → 供给配置 → 库存平衡 → 计划确认

最终实现：将市场需求转化为可执行的供需决策，实现需求满足与库存效率的平衡。

2. WHY｜为什么做价值流分析

  • 看价值：从部门/流程视角转向端到端价值视角
  • 找断点：识别价值创造中的阻塞、浪费和损失
  • 建架构：连接战略、价值流、能力、流程和 IT
  • 促转型：找到业务优化、数字化和 AI 的价值机会
核心目的：不是把流程画全，而是看清“价值如何产生、在哪里损失、如何提升”。

3. HOW｜如何开展价值流分析

① 明确范围：业务领域、价值对象、核心 Stakeholder
↓
② 识别价值流：从经营目标出发识别企业核心端到端价值流
↓
③ 定义价值流：明确 Trigger、Value Proposition、Outcome
↓
④ 拆解 Stage：识别 4–7 个关键价值创造阶段
↓
⑤ 建立映射：Value Stream / Stage → Capability → Process → System
↓
⑥ 识别优化机会：价值损失 → 能力差距 → 数字化 / AI 机会 → KPI

4. 判断标准（六看）

判断维度 核心问题
看价值是否明确创造什么业务价值？
看边界Trigger 和 Outcome 是否清晰？
看端到端是否形成完整价值闭环？
看 Stage是否体现价值递进，而非简单流程步骤？
看粒度同层级价值流是否保持一致粒度？
看结果是否能够关联经营结果和 KPI？
好的价值流分析 = 价值清晰 + 边界合理 + 端到端 + 阶段递进 + 粒度一致 + 可衡量

活动类型：客户沟通

# 伊利奶粉事业部「分仓补货计划」业务解读 ## 一、业务背景 ### 业务链路 伊利奶粉事业部的分仓补货业务，覆盖从生产工厂、基地仓、销售分仓，到线上线下渠道客户的供应链补货链路。 整体链路可以概括为： 工厂 / 基地仓 → 销售分仓 → 电商及经销商 → 终端客户 业务涉及的上游节点包括： - 8 个国内工厂 - 1 个 ODL 工厂 - 4 个基地仓 - 多个区域销售分仓 - 线上电商渠道与线下经销商渠道 其中，基地仓包括天津基地仓、呼市基地仓、杜蒙基地仓、武汉基地仓等；销售分仓包括合肥、天津、广州、郑州、成都、武汉、呼市、济南、柳州等销售仓。 ### 组织边界 - **组织范围**：伊利奶粉事业部 - **业务范围**：伊利奶粉事业部所属生产工厂到各分仓 of 补货业务 - **商品范围**：伊利奶粉事业部经营的所有在售商品，不包含促销品及礼盒 - **覆盖供应链网络节点**：工厂仓、区域分仓 - **渠道范围**：线上电商、线下经销商 ### 业务本质和目标 未来需要建立一套面向奶粉事业部的分仓补货计划机制，使生产、物流、销售分仓和渠道需求之间形成更高效、更准确、更可控的协同关系。奶粉业务具有较强的供应链复杂性： - 渠道多，包括线上电商、KA 客户、经销商、母婴、商超、特渠等 - 仓网多，包括工厂仓、基地仓、区域分仓 - 商品对日期和新鲜度敏感 - 区域需求波动明显 - 缺货会影响订单满足和客户体验 - 库存过高会影响周转和新鲜度 因此，分仓补货计划既要解决“货够不够”的问题，也要解决“货在哪里、是否新鲜、是否在正确的仓、能否及时满足订单”的问题。 ## 二、业务现状与潜在问题 ### 当前业务流程现状 当前分仓补货计划主要涉及三个业务板块：销售 → 物流 → 生产供应。 其中： - **销售侧**：制定销售计划，调整销售计划，整理区域原始需求。 - **物流侧**：负责产销协同、生产主计划、排程、基地仓到销售仓的分货计划，以及基地仓到销售仓的补货订单。 - **生产供应侧**：负责原奶供应及产能、工厂生产、基地仓入库。 现有流程已经具备跨部门协同机制，但关键环节仍然高度依赖人工、Excel 和经验判断。 ### 问题一：当前以“推式分货”为主，需求响应偏被动 现有模式主要是“推式分货”为主，即根据生产备货率、库存天数、分配后缺口等指标，由上游向销售仓进行分配。 - **特点**：从生产和库存供给角度出发，更关注上游有什么货、如何分出去，对下游真实需求变化的响应相对滞后。 - **潜在问题**：区域需求快速变化时分货调整不及时，易出现部分仓缺货、部分仓积压，难以及时反映渠道订单与销售节奏。 ### 问题二：销售计划整理依赖人工，需求输入颗粒度不足 当前销售计划需要按区域、营销总部归属等维度进行人工整理，再加工到分仓维度。 - **痛点**：销售计划从区域到分仓维度的转化成本高，人工整理耗时耗力，数据口径可能不统一，需求趋势识别不足。 ### 问题三：分货计划依赖 Excel，系统化和智能化程度不足 当前基地仓到销售仓的分货计划主要依赖 Excel 和调度组处理。 - **痛点**：数据收集和整理工作量大，分货决策依赖人工经验，复杂场景下难以兼顾库存、需求、新鲜度、在途等多重因素。 ### 问题四：库存监控依赖人工，横向调拨不够及时 当前销售仓和基地仓库存主要由仓内大日期库存人工监控。 - **痛点**：库存风险发现滞后，仓间不均衡难以及时纠偏，部分仓缺货时容易触发跨仓履约。 ### 当前整体问题总结 **需求输入不够精细 → 分货模式偏推式 → 计划形成依赖人工 and Excel → 库存监控与调拨响应不及时 → 导致分货效率、分仓有货率、库存周转、新鲜度和订单满足存在提升空间。** ## 三、当前业务升级目标 ### 总体升级方向 通过推拉模式设计、销售计划精细化、分仓智能补货优化和销售仓横向调拨，构建更智能、更高效、更均衡的分仓补货计划体系。 ### 核心专题 1. **推拉模式设计**：探索“推拉结合”模式，明确上游推与下游拉的协同边界。 2. **销售计划精细化**：第一道防线，提升需求输入质量，减少人工整理。 3. **分仓智能补货优化**：第二道防线（核心），从人工 Excel 分货转向系统化、智能化的补货建议。 4. **销售仓横向调拨**：第三道防线，实现分仓之间的动态纠偏，降低跨仓履约。 ### 最终目标：四个提高，一个降低 - **提高分货效率**：减少人工制表与核算时间。 - **提高分仓有货率**：减少区域性缺货。 - **提高库存周转率**：优化库存分布。 - **提高新鲜度**：兼顾库存数量与商品日期。 - **降低跨仓履约**：降低额外物流成本，提升履约时效。

2.5 优先级评估

5 分钟
  • WHAT：从业务价值和实现难度两个维度对场景进行打分筛选，锁定首个 MVP
  • WHY：确保有限的研发资源投入在“高 ROI”且“能落地”的场景上
  • 工具：价值-可行性四象限、数据准备度评估表

实操指南 (HOW)

借助 AgentOS 桌研
利用 AgentOS 进行数据驱动的优先级评估，确保资源投入到高 ROI 的场景： 1. **录入场景数据**：将初步 SLP 清单及现场获取的数据情况输入 AgentOS。 2. **多维打分推演**：利用 AgentOS 预置的评估模型，从业务价值（降本增效幅度、Sponsor 关注度）和技术可行性（数据质量、大模型能力边界）两个维度进行模拟打分。 3. **识别数据风险**：通过 AgentOS 的合规引擎分析场景是否涉及敏感数据或缺乏历史语料，输出“数据准备度 (Data Readiness)”警告。 4. **生成优先级矩阵**：AgentOS 自动绘制“价值-可行性四象限图”，推荐位于“Quick Win”象限的首批 MVP 场景。

3.1 需求目标与 KPI

4 分钟
  • WHAT：将场景成效与客户的战略 KPI 进行强绑定，定义清晰的成功指标
  • WHY：让 AI 的价值从“玄学”变成“数学”，为项目立项和 ROI 测算提供决策依据
  • 工具：OSM 模型、业务基准 (Baseline) 数据表

实操指南 (HOW)

客户沟通
**1. 从 AgentOS 衔接出沟通事项** - 基于 AgentOS 的价值预估，梳理出与高优场景相关的 2-3 个核心业务指标（如：人力成本、交付周期）。 **2. 结合调研事项，准备沟通计划** - 与财务或销售运营部门预约沟通，目标是获取当前流程的基准数据 (Baseline)。 - 准备好 OSM 模型 (Objective-Strategy-Measurement) 框架。 **3. 如何沟通 (执行)** - **对齐 Baseline**：询问现状数据（例如“目前制作一份提案的平均周期是多少？”）。 - **设定改进目标**：与业务负责人探讨 AI 介入后的合理“改进目标值”（如缩短周期 30%）。 - **指标拆解**：将业务“北极星指标”拆解为 AI 的具体表现指标（如：检索准确率、初稿采纳率）。 **4. 沟通注意事项** - ⚠️ KPI 必须是客户现有系统能统计出来的。如果你定义了一个系统无法监控的指标，那么在项目结束时，你将无法证明 AI 到底带来了多少价值。

3.2 业务动作识别

6 分钟
  • WHAT：拆解 AI 介入后，人与 AI 交互的具体业务动作序列
  • WHY：识别数据输入的来源、AI 处理的逻辑断点以及人工复核的心理阈值
  • 工具：原子动作分解模板、人机协作边界图

实操指南 (HOW)

借助 AgentOS 桌研
利用 AgentOS 的逻辑编排能力，拆解 To-be 流程的“原子动作序列”： 1. **输入现状与目标**：将 As-is 流程和业务 KPI 输入 AgentOS。 2. **生成原子动作**：让 AgentOS 拆解出人与 AI 交互的具体序列（用户上传什么？AI 提取什么？在哪里等待人工确认？）。 3. **识别数据依赖**：通过 AgentOS 分析每个动作所需的上下文数据 (Context)。 4. **划定人机边界**：明确哪些动作是 AI 建议，哪些是必须由人执行的终审决策。

7 分钟

1. 全流程回顾

  • 理需求三部曲：懂业务 (客户研究) -> 找痛点 (场景发现) -> 定方案 (场景定义)
  • 核心价值：通过“理需求”将模糊的客户诉求转化为结构化的 AI 场景规划 (SRP)，为后续交付打好地基

2. AgentOS 实操演示 (关键环节展示)

  • 桌研提效演示 (Desk Research)
    • 演示如何使用 AgentOS 聚合搜索 Ascentium 及伊利奶粉所在的行业报告，并在 30 秒内提取出核心价值流模型
    • 展示如何通过 AgentOS 对 20 份历史访谈录音或业务痛点记录进行语义聚类，自动生成包含“痛点频率”的热力图（如伊利的“跨仓履约”痛点）
  • 共创产出演示 (Co-creation)
    • 演示如何使用 AgentOS 辅助生成初版“场景画布”：输入痛点清单，AI 自动推荐 RAG + Agent 或大模型智能补货调度的架构组合
    • 展示基于 Ascentium 与伊利业务逻辑自动推演出的 MoS 指标建议（包含数据获取方式说明）

3. 核心精神总结

  • 以业务价值为导向：所有的 AI 场景必须最终关联到客户的战略 KPI
  • Start with 50%-ready：善用 AgentOS 提效，永远带着“假设”去共创
  • 可视 = 价值：用原型 and Demo 锁定客户预期，减少交付偏差
