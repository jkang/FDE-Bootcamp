# 分仓智能补货 Agent 原型

这份原型对应 SDP-Product 阶段 2 的故事线演示，根植于「分仓智能补货」场景的 To-Be 旅程与补调决策规则。

## 设计系统锚定（本原型使用的视觉基底）

- **锚定优先级：** P3 中性默认
- **锚定来源：** 无（FDE 未提供客户品牌规范/参照物）
- **锁定状态：** ⚠️ 未锁定
- **设计系统文档：** [`DESIGN.md`](./DESIGN.md)
- **可视化预览：** [`preview.html`](./preview.html)

> 如果客户方未来提供正式规范，只需替换 `DESIGN.md` 对应条目 + `assets/tokens.css` 对应 CSS 变量，HTML 页面无需重做。

## 如何运行

双击 `index.html`，任意现代浏览器，无需 server。首次打开需联网加载 Tailwind CDN 与 Inter 字体（离线时布局/字体降级，交互仍可用）。

## 走查路径（推荐按顺序）

1. 先看 **`preview.html`** —— 确认视觉基底（P3 中性默认）是否符合预期
2. 故事线 1 · **九点异常总览与缺口识别** —— AI 一屏识别全国仓网谁缺货谁积压
3. 故事线 2 · **分货方案推理与人工确认** —— 多约束算分配量 + HITL 拦截
4. 故事线 3 · **事件驱动临时补调** —— 天津入库延期，打破 routine 给组合方案
5. 故事线 4 · **补货单下发与经验沉淀** —— 一键下发（可撤销）+ 人工反馈沉淀为规则

## 每条故事线的演示点

| 故事线 | 业务价值高光 | 对应 SRP 阶段 | 演示的必备交互 | 规则承接 |
|---|---|---|---|---|
| ① 九点异常总览 | 全仓网缺口/积压一屏识别 | P1 货源评估 | #1 流式 #2 工具调用 #7 出处引用 #8 状态徽章 | 决策模型类（缺口分级）· 关联关系类 |
| ② 分货方案推理 | 多约束算分配量，人只确认 | P2 分货方案 | #4 内联组件 #5 HITL #7 出处引用 | 决策模型类（备货率/目标备货率）· 模版范例类 |
| ③ 事件驱动临时补调 | 事件打破 routine 自动重算 | P2 异常分支 | #2 工具调用 #7 出处引用 #9 错误态 | 决策模型类（可发量约束/就近优先） |
| ④ 补货单下发与沉淀 | 一键下发可撤销，反馈成规则 | P3-P5 | #6 撤销 #10 空态 | 操作流程类（校验规则）· 决策模型类（复盘调参） |
